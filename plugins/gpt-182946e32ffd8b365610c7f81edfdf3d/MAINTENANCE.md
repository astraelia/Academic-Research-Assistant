# 学术研究助手维护约定

本目录是插件 `gpt-182946e32ffd8b365610c7f81edfdf3d` 的可编辑本地源码；本仓库的 `plugins/` 目录是后续正式维护位置，GitHub 用于版本管理与备份。通过 `astraskye-local` marketplace 安装本地版本。外部独立安装的六个同名 Skill 暂时保留作迁移回退，不再作为新功能的上游源码，也不要修改后再复制进本目录。

## 日常升级

- 精读方法、总结模板、解析规则、课程学习步骤或知识库维护细节：修改对应 `skills/<name>/`，运行该 Skill 的校验与相关脚本测试，再提交同一插件的新版本并重新安装本地版本。
- 共享论文身份与交接规则：修改 `references/paper-identity-and-handoff.md`，检查调用它的工作流。
- 总结/精读共用笔记校验逻辑：只改根目录 `scripts/validate_note.py`。两个 Skill 内同名脚本仅为旧调用入口，必须保持转发逻辑，不放第二份校验实现。
- 新增、删除、改名 Skill，改变输入输出、跨 Skill 顺序、写入归属或 Tool/MCP 依赖：同时审查 `skills/instructions/SKILL.md`、manifest、相关 Skill 的描述和交接契约；运行全部路由场景检查。

发布时保留原插件 `name`、图标、三条 `defaultPrompt` 的类型与顺序，递增两个 manifest 的版本，运行相关脚本测试并校验清单、Skill 和资源路径，将源码提交到本仓库，再通过本地 marketplace 重新安装和核验。不要直接修改安装缓存；GitHub 提交不会自动刷新缓存。若另行授权更新云端账号插件，应使用原插件的 `current_release_id` 作受保护更新。账号更新工具对文件采取覆盖叠加，**省略文件不会删除旧版本中的文件**；实际删除或重命名需先确认发布机制支持的清理方式，不能把本地删除误认为线上已删除。

## 术语管理验证

`terminology-management` 使用根目录 `scripts/terminology.py` 管理状态和写入。修改身份、完成门禁、锁、断点或实体增量规则时，运行 `tests/test_terminology.py`，并核对三个文献入口及 `references/terminology-handoff.md`。辅助脚本无需额外依赖；科学判断和实际外部条目阅读仍由 Skill 完成。测试只使用隔离合成夹具，不代表真实文献已经入库。

修改模板正文生成时，必须使用包含真实章节、五项学术表达栏目和证据／维护表格的夹具；检查创建、增量、重复执行、模板顺序与自定义栏目，以及正文缺失时写入、完成和审计是否拒绝。属性校验不能代替正文验收。历史卡片修复需显式授权，先备份并验证预览，再在原路径检查并发变更后写入；保留 ID、定义、来源、个人备注和机器检查点，不为格式修复重开论文筛查。

## 迁移期检查

同名外部 Skill 与插件 Skill 同时可被发现；使用本插件时以插件内 Skill 为准。稳定使用一段时间后，才逐个检查外部副本是否仍被其他流程、脚本、引用、资产或历史路径依赖。删除之前要在不依赖外部副本的环境下验证文献总结、精读、登记、全文解析、课程处理、知识库维护和组合流程；未完成这些验证时保留独立副本。真实 Vault 的目录和规则始终在运行时重新发现。
