# MinerU parse review contract

`review.py` works on one staging folder:

```text
STAGE/
├── paper.md             # corrected MinerU export
├── parse-audit.json     # page and element review evidence
├── parse-review.md      # generated from parse-audit.json; do not edit directly
└── assets/parsed/       # usable figure images; PDF crops only when a figure needs correction; no table/equation crops
```

Run `review.py init` after the full parse is complete. It creates one pending audit entry for **each page in the original PDF**, checks the PDF hash and independent page count, and saves a `source_pdf` path and MinerU locator. Edit only the page/visual/correction entries by hand or through a structured editor. Run `review.py sync` to update `review_status`, `checked_pages`, `open_issues`, and the Markdown review report.

## Audit fields

The following one-page example has a corrected figure. A real audit must list every original PDF page exactly once.

```json
{
  "schema_version": 1,
  "source_pdf": "<PDF_PATH>",
  "pdf_sha256": "64 lowercase hexadecimal characters",
  "pdf_page_count": 1,
  "mineru_locator": "doc:example/tier:standard",
  "visual_format_policy": "figures-as-images-tables-equations-as-markdown-v1",
  "review_status": "partial",
  "checked_pages": [],
  "open_issues": [],
  "pages": [{
    "page": 1,
    "pdf_locator": "doc:example/tier:standard/page:1",
    "text_status": "matched",
    "text_anchor": "a literal phrase present in paper.md",
    "layout_status": "matched",
    "visual_inventory_complete": true,
    "visuals": [{
      "kind": "figure",
      "label": "Fig. 1",
      "pdf_locator": "doc:example/tier:standard/page:1/block:4",
      "status": "corrected",
      "paper_anchor": "![Fig. 1](assets/parsed/fig-1.png)",
      "asset": "assets/parsed/fig-1.png"
    }],
    "notes": "Compared all text, both figure panels, legend, and caption with the PDF page."
  }],
  "corrections": [{
    "page": 1,
    "kind": "figure",
    "label": "Fig. 1",
    "pdf_locator": "doc:example/tier:standard/page:1/block:4",
    "problem": "The parsed figure omitted the right panel.",
    "change": "Replaced it with a crop showing both panels and the legend.",
    "result_anchor": "![Fig. 1](assets/parsed/fig-1.png)",
    "status": "resolved"
  }]
}
```

- `text_status` and `layout_status`: `pending`, `matched`, `corrected`, `unresolved`, or `not_applicable`. A `not_applicable` page needs a reason in `notes`; use it for genuinely blank or image-only pages, not unread text. Completed text needs a literal `text_anchor` found in the final `paper.md`.
- `visual_inventory_complete`: set `true` only after visually inspecting the **PDF** page for figures, tables, and equations. Add a brief page-specific `notes` entry describing what was checked. `visuals: []` means the inspected page has none. MinerU's output is not an inventory of what the PDF contains.
- Each visual uses `kind: figure|table|equation`, a label, original-PDF locator, `status: pending|matched|corrected|unresolved`, and a literal `paper_anchor` for completed items. Figures require a usable local image under `assets/parsed/`; if accurate image content has only a packaging/link issue, copy the existing file if needed and repair its relative link without altering it. Crop from the PDF only when image content is missing, incomplete, or wrong, or remains unusable after path repair. Tables must use Obsidian-compatible Markdown pipe-table rows; equations must use inline or display Markdown math. Preserve already accurate Markdown without rewriting it. Never crop tables or equations into images. New audits initialized by `review.py` carry `visual_format_policy: figures-as-images-tables-equations-as-markdown-v1`; its gate requires a figure asset and rejects image assets for tables/equations. Older audits without the policy remain readable.
- Each correction uses `page`, `kind`, optional `label` (required to match a visual), original-PDF locator, `problem`, `change`, literal `result_anchor` in final Markdown, and `status: resolved|open`. Text/layout corrections omit `label`. A corrected status needs a corresponding resolved record. An unresolved status needs an open record.
- `review_status`, `checked_pages`, and `open_issues` are generated by `review.py sync`. A page counts as checked only when text, layout, and the full visual inventory are accounted for. An open issue or any unchecked page keeps the review `partial`.

## Verification boundary

`review.py check STAGE --source-pdf PDF_PATH --require-verified` confirms: original PDF hash and page count, complete page entries, recorded status and corrections, current review report, local figure paths/links, and Markdown formatting for tables and equations when the new visual policy is present. It cannot detect a figure omitted from a falsely declared visual inventory, or prove that OCR text/table cells match the PDF. The reviewing agent must compare the source page images and corrected output before setting statuses; the tool makes omissions in the **recorded process** visible and blocks incomplete imports.
